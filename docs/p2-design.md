# P2「日常可用」設計

依據計畫書 §8 的 P2 範圍、D2（格式轉換、CUE 分軌、附屬檔案）與 D6（Drive 收件匣匯入）。使用者 2026-10-02 指示「實作 P2」；各項細節由 Claude 決定，完成一個階段回報一次。

## 範圍與已完成部分

| 計畫書 P2 項目 | 狀態 |
|---|---|
| 歷史 | 播放紀錄已在 D9 完成；P2 補歷史頁與播放次數 |
| 重啟恢復 | 匯入、上傳、下載已可續做（B2–B4）；P2 補新流程（轉換、分軌、RSS）與實測 |
| 低磁碟管理 | 選檔時已檢查暫存預算與保留空間（B3）；P2 補全域監控與日誌輪替 |
| 共用音檔／跨專輯收錄 | 資料模型已支援（同一 asset 多個收錄）；P2 由預覽與編輯操作補上使用方式 |
| 其餘 | 本文件各階段 |

## 階段

| 階段 | 內容 |
|---|---|
| P2-1 個人化 | 收藏（歌曲、專輯）、歌單、歌詞（內嵌、LRC、手動）、歷史頁與播放次數 |
| P2-2 整理 | 資料庫覆寫標籤的編輯、修改紀錄與撤回、恢復原標籤、專輯合併／拆分、日文別名、假名不分的搜尋 |
| P2-3 匯入預覽 | 匯入先分析再執行：分組預覽、批次修正、「每個子資料夾是一張專輯」；ZIP；附屬檔案（CUE、LOG 上傳為旁附檔，LRC 作歌詞） |
| P2-4 轉換與分軌 | FFmpeg：無損格式轉 FLAC（PCM MD5 驗證）、CUE＋整軌實體分軌（串接 PCM MD5 驗證）、匯入來源去重 |
| P2-5 RSS | 來源管理、Nyaa 範本、輪詢與退避、去重、包含／排除規則、可選自動下載（預設關閉、首次只建基準） |
| P2-6 Drive 與資源 | Changes API 增量對帳、Drive 收件匣匯入（D6）、低磁碟監控、日誌輪替、重啟恢復實測 |

## P2-1 個人化

### 資料

- 收藏：`favorite_tracks`、`favorite_albums`，刪除歌曲或專輯時一併移除。
- 歌單：`playlists`；`playlist_items` 有獨立 ID、`track_id`、可選的 `album_id`（從哪張專輯加入，決定封面與播放脈絡）與 `asset_id`（指定音檔版本，空值表示歌曲的預設音檔）、排列位置；允許重複歌曲（計畫書 §5）。
- 歌詞：`lyrics` 每首歌曲一份，記錄來源（`embedded`／`lrc`／`manual`）與是否有時間軸。手動編輯的歌詞不會被之後的匯入覆蓋。

### 歌詞來源

- 內嵌：Vorbis comment 的 `LYRICS`／`UNSYNCEDLYRICS`、ID3 `USLT`、MP4 `©lyr`。
- LRC：與音檔同主檔名的 `.lrc`；編碼依 D2 第 4 點（BOM → UTF-8 → CP932）。
- 已入庫的 FLAC／Ogg 歌曲：原始標籤已存在 `import_items.info`，遷移時直接回填，不必重新下載。
- 時間軸格式 `[mm:ss.xx]`，含 `[offset:]`；播放頁同步顯示目前一行，點一行可跳到該處。

### 播放次數與歷史

- 播放次數＝達到 D9 門檻（`counted`）的播放數。
- 歷史頁：最近的播放（含時間、從哪張專輯播放），以及近 30 天最常播放的歌曲。

### 網頁端

- 歌曲列右側「更多」選單：下一首播放、加入佇列、加入歌單、收藏、前往專輯。
- 專輯頁：收藏專輯、整張加入歌單。
- 正在播放：收藏、歌詞（寬螢幕在右側取代佇列；手機以分頁切換「佇列／歌詞」）。
- 曲庫分頁增加「歌單」「收藏」；歌單頁可改名、刪除、移除項目、拖曳排序。
- 收藏狀態由客戶端一次載入全部 ID 後在本地判斷，所有清單共用，不必每個查詢都帶旗標。

## P2-2 整理

- 編輯只改資料庫，不改寫音檔（計畫書 §4）。可編輯：歌曲（曲名、歌手、版本說明、類型）、專輯（名稱、專輯歌手、日期、型號、版本、封面、整張的類型）、收錄（碟號、曲序）。
- 每個操作是一個「修改群組」（`edit_groups`），逐欄記在 `edits`：對象、欄位、舊值、新值；來源為 `user`／`identify`／`restore`／`undo`。撤回只還原該群組改過、且目前仍是當時新值的欄位；之後又被改過的欄位保留並列出（計畫書 §4「撤回不覆蓋後續人工修正」）。撤回本身也是一個群組，可以再撤回。
- 匯入身分（`origin`）：專輯記下建立它的「專輯名稱＋專輯歌手」標籤，收錄記下「專輯標籤＋碟號＋曲序」。改名、合併、拆分、重新編號之後，同一檔案以同樣標籤再匯入仍視為同一收錄，不會長出舊名字的專輯；新檔案以舊標籤匯入則加入改名後（或合併後）的專輯。手動拆分出的專輯沒有 origin，匯入不會自行加入。
- 恢復原標籤：取 `import_items.info` 保存的原始標籤，以匯入時的規則重新解讀；專輯的名稱與專輯歌手取自 origin（含當時由同資料夾決定的專輯歌手）。專輯恢復時，合併進來的收錄回到原專輯、拆分出去的收錄回到這張；型號、版本與 MusicBrainz 連結清除，別名與封面保留。恢復也寫入修改紀錄、可撤回。
- 合併：把一張專輯的收錄移到另一張；同一音檔已在目標專輯的收錄不重複加入（移除並記下整列，撤回可放回）；被併掉的專輯記下 `merged_into`，之後用它的標籤匯入的檔案也歸到目標。收藏跟著移到目標。拆分：選取收錄移到新專輯（沿用專輯歌手、日期、封面）。
- 沒有收錄的專輯（合併或移除後）不出現在清單，但保留資料列，讓撤回能把收錄放回；專輯頁顯示「已合併到…」與「恢復原分組」。
- 移除專輯（可撤回）只解除收錄，歌曲留在「歌曲」分頁。永久刪除另外確認：歌曲連同收錄、歌單項目、收藏、歌詞、播放記錄刪除；沒有其他歌曲使用的音檔從曲庫移除並移到 Drive 垃圾桶（30 天內可在 Drive 還原）；共用音檔不動（計畫書 §8 驗收）。
- 別名：`aliases` 讓歌手、專輯、歌曲有其他名稱（羅馬字、舊名、簡稱），一併建入搜尋索引。歌手改名時，新名稱接手別名，並把舊名加為別名。
- 搜尋正規化：NFKC、小寫、片假名轉平假名，並去掉空白、標點與符號（長音「ー」保留）；索引每個名稱一行，查詢不會跨名稱比對。只有符號的查詢（例如「%」）改用保留符號的版本比對。索引在服務啟動時依正規化版本自動重建。

### 輔助辨識（MusicBrainz）

- 只在使用者按「搜尋」時查詢，送出的只有專輯名稱、歌手、型號、年份與歌曲數；不送音檔。MusicBrainz 不需要 key，User-Agent 帶 `Kanade/版本 ( 服務網址 )`，請求間隔 1.1 秒，回應快取 1 小時（圖片不快取）。
- 候選：專輯名稱逐字比對（加歌手）或型號；另外以歌手搜尋找到 MusicBrainz 上的歌手（會比對別名與排序名），列出該歌手同年份（或同曲數）的發行。羅馬字標籤的日本發行（「Euforia」／「Makino Yui」）只有這條路找得到（「ユーフォリア」／牧野由依）。曲數與年份相符的排前面。
- 選定發行後列出差異：專輯名稱、專輯歌手、日期、型號，各曲的曲名、歌手；曲序相同時依碟號與曲序配對，沒有曲序但數量相同時依順序配對並一併提出曲序。檔案長度與 MusicBrainz 相差超過 5 秒的歌曲標示「長度不符」，預設不勾。可另選 Cover Art Archive 的封面，並記下 MusicBrainz 發行與錄音 ID。
- 套用是一個 `identify` 修改群組，可撤回；不會因分數高就自動套用（計畫書 §4）。AcoustID 指紋辨識需要 application key，仍待決定，未實作。

## P2-3 匯入預覽

- 批次狀態：`analyzing → review → running → done`，另有 `canceled`。分析階段展開壓縮檔、讀標籤，不雜湊不上傳，為每個檔案定「匯入計畫」（`import_items.plan`：所屬組、專輯、專輯歌手、日期、碟號、曲序、曲名、歌手、類型）；執行階段照計畫入庫，不再逐檔重新判斷。
- 停在 `review` 的：網頁上傳（客戶端帶 `preview: true`）；伺服器資料夾匯入由 API 參數決定。BT 下載直接執行（選檔時已看過內容），之後用 P2-2 的編輯整理。API 預設不預覽，既有的上傳腳本不受影響。
- 預覽每組顯示：專輯、專輯歌手、日期、歌曲數、資料夾、會加入曲庫中的哪張專輯或是新專輯，以及提示（缺專輯歌手、曲序不完整或重複、文字已損毀、編碼為猜測、與曲庫同一音訊但標籤不同（D2 第 6 點，以 FLAC 的音訊 MD5 判斷））。不匯入的檔案（格式不支援、無法讀取、手動排除）與附屬檔案另列。
- 修正：整組改專輯名稱、專輯歌手、日期、類型；改單曲欄位；把檔案移到另一組、新專輯或改為單曲；整組拆成單曲；「每個子資料夾是一張專輯」（資料夾內檔案有同一專輯標籤時沿用，否則用資料夾名）；排除與重新加入；按批次改用其他文字編碼（CP932、GBK、Big5、Latin-1）重新解碼——改編碼會依新的標籤重新規劃，先前的修正不保留。
- 匯入身分：每個檔案記下標籤本身給的專輯、碟號、曲序（`tagged`），預覽怎麼改都不變，之後同一檔案再匯入時以它判斷是否為同一收錄。每組另有「錨點」：組內多數檔案的專輯標籤；組的第一個檔案以錨點找到或建立專輯，同組其他檔案跟著它，因此合併、改名後整組一定落在同一張專輯。同一批兩組錨點相同時，後面的一組另建專輯。
- ZIP：分析時先檢查再展開：項目數 ≤ 5,000、單檔 ≤ 4 GB、壓縮比 ≤ 100 倍、不得有路徑逃逸（`..`、絕對路徑、磁碟代號）、只取音檔／CUE／LOG／LRC／圖片，展開總量須在暫存預算與磁碟保留空間內；任一項不符整個壓縮檔不展開並說明原因。檔名依 D2 第 4 點解碼（無 UTF-8 旗標的 CP932 檔名可正確顯示）。展開到 `staging/work/<批次>`，計入共用暫存預算；每個檔案處理完即刪，整批沒有失敗時刪除整個工作資料夾；上傳的 ZIP 展開後即刪（伺服器資料夾裡的不動）。
- 附屬檔案（D2 第 5 點）：CUE、LOG 在同批音檔之後處理，上傳到 Drive `sidecars/<專輯歌手>/<專輯>`，記在 `sidecars` 並掛在同一資料夾匯入的專輯下；專輯頁列出並可下載。LRC 作為歌詞（P2-1），掃描圖仍只上傳選中的封面。
- 取消：等待確認或分析中的批次可以取消；不上傳任何東西，刪除展開的檔案，網頁上傳的暫存檔一併刪除。

## P2-4 轉換與分軌

- FFmpeg 位置：`KANADE_FFMPEG`，或資料目錄旁 `tools/ffmpeg`；不存在時這類檔案標示原因、其他照常（D2 第 7 點）。同時只跑一個，`nice` 降低優先權。
- 轉 FLAC：APE、TAK、WavPack、TTA、ALAC、WAV、AIFF；保留取樣率、位元深度、聲道與標籤。來源與輸出解碼後的 PCM MD5 必須相同。
- CUE 分軌：依 INDEX 01 切點逐首輸出 FLAC，pregap 併入前一軌，首軌之前的隱藏音軌為第 0 軌；以取樣數切割（CD 為每幀 588 個取樣），各軌 PCM 依序串接的 MD5 必須等於整軌 PCM MD5。CUE 的 TITLE、PERFORMER、REM DATE、DISCNUMBER、CATALOG 作為原始標籤。
- 轉換與分軌在分析階段完成，輸出放在 `staging/work/<批次>`，計入暫存預算；處理前先檢查空間。
- `import_sources` 記錄來源檔 SHA-256 與大小對應到的音檔；同一來源再次匯入直接略過。

## P2-5 RSS

- 來源：名稱、URL、更新間隔（預設 30 分鐘、最短 10 分鐘）、啟用、自動下載（預設關閉）、包含／排除規則。提供 Nyaa 範本（`https://nyaa.si/?page=rss&c=2_1&f=0&q=`，可改分類與關鍵字）。
- 輪詢：單一工作程序；依下次時間排程並加隨機錯開；帶 ETag／Last-Modified；回應上限 5 MB、每次最多 500 條；失敗指數退避（最長 6 小時）。
- 解析 RSS 2.0 與 Atom；辨識 enclosure torrent、`.torrent` 連結、magnet、`nyaa:infoHash`（組成 magnet）、`nyaa:size`、`nyaa:seeders`。只有詳情頁的條目標示「無法直接下載」。
- 去重：來源＋GUID 唯一；正規化連結與 infohash 用來合併不同來源的同一種子、標示已下載過。每個來源保留最近 1,000 條。
- 規則：包含規則每行一組，行內所有詞都要出現、任一行符合即可；排除規則任一行符合就排除；比對前做 P2-2 的正規化。
- 自動下載：啟用後，只對「啟用之後新出現」的條目生效（首次與每次啟用都先建立基準）；建立下載後自動採用預設勾選，空間不足時停在選檔並顯示原因。
- 搜尋：預設在已取得的條目中篩選；Nyaa 這類網址含 `q=` 的來源可「在來源站內搜尋」，結果即時取得、不入庫。

## P2-6 Drive 與資源

- 增量對帳：保存 Changes API 的 page token，每 10 分鐘取一次變更。曲庫音檔被刪除或移到垃圾桶時標為 `missing`（不刪資料），恢復後回到 `verified`；首頁「待整理」顯示遺失數量。手動「完整對帳」分批列出平台資料夾，比對所有已知 file ID。
- 收件匣（D6）：平台資料夾下的 `inbox/`。音檔以 Range 讀檔頭解析、用 Drive 的 `sha256Checksum` 去重，再以伺服器端移動歸入 `library/`，不重新上傳；圖檔可作封面；不支援的格式下載到暫存走一般轉換流程。
- 低磁碟：每 30 秒檢查一次。低於保留空間時依序：清可淘汰快取 → 停止預載 → 暫停進行中的下載、拒絕新上傳與新下載；未上傳的資料不刪。恢復後自動繼續被暫停的下載。狀態顯示在任務頁。
- 日誌：服務自己寫檔並輪替（10 MB × 5）。
- 重啟恢復實測：在上傳、匯入、轉換、下載進行中強制結束服務，確認重啟後能接續且不產生重複遠端檔案。
