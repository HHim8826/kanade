# P2「日常可用」設計

依據計畫書 §8 的 P2 範圍、D2（格式轉換、CUE 分軌、附屬檔案）與 D6（Drive 收件匣匯入）。使用者 2026-10-02 指示「實作 P2」；各項細節由 Claude 決定，完成一個階段回報一次。

## 範圍與已完成部分

| 計畫書 P2 項目 | 狀態 |
|---|---|
| 歷史 | 播放紀錄已在 D9 完成；P2 補歷史頁與播放次數 |
| 重啟恢復 | 匯入、上傳、下載已可續做（B2–B4）；P2 補新流程（轉換、分軌、RSS）與實測 |
| 低磁碟管理 | 選檔時已檢查暫存預算與保留空間（B3）；P2 補全域監控與日誌輪替 |
| 共用音檔／跨專輯收錄 | 資料模型已支援（同一 asset 多個收錄）；P2 由預覽與編輯操作補上使用方式 |
| 其餘 | 本文件各階段 |

## 階段

| 階段 | 內容 |
|---|---|
| P2-1 個人化 | 收藏（歌曲、專輯）、歌單、歌詞（內嵌、LRC、手動）、歷史頁與播放次數 |
| P2-2 整理 | 資料庫覆寫標籤的編輯、修改紀錄與撤回、恢復原標籤、專輯合併／拆分、日文別名、假名不分的搜尋 |
| P2-3 匯入預覽 | 匯入先分析再執行：分組預覽、批次修正、「每個子資料夾是一張專輯」；ZIP；附屬檔案（CUE、LOG 上傳為旁附檔，LRC 作歌詞） |
| P2-4 轉換與分軌 | FFmpeg：無損格式轉 FLAC（PCM MD5 驗證）、CUE＋整軌實體分軌（串接 PCM MD5 驗證）、匯入來源去重 |
| P2-5 RSS | 來源管理、Nyaa 範本、輪詢與退避、去重、包含／排除規則、可選自動下載（預設關閉、首次只建基準） |
| P2-6 Drive 與資源 | Changes API 增量對帳、Drive 收件匣匯入（D6）、低磁碟監控、日誌輪替、重啟恢復實測 |

## P2-1 個人化

### 資料

- 收藏：`favorite_tracks`、`favorite_albums`，刪除歌曲或專輯時一併移除。
- 歌單：`playlists`；`playlist_items` 有獨立 ID、`track_id`、可選的 `album_id`（從哪張專輯加入，決定封面與播放脈絡）與 `asset_id`（指定音檔版本，空值表示歌曲的預設音檔）、排列位置；允許重複歌曲（計畫書 §5）。
- 歌詞：`lyrics` 每首歌曲一份，記錄來源（`embedded`／`lrc`／`manual`）與是否有時間軸。手動編輯的歌詞不會被之後的匯入覆蓋。

### 歌詞來源

- 內嵌：Vorbis comment 的 `LYRICS`／`UNSYNCEDLYRICS`、ID3 `USLT`、MP4 `©lyr`。
- LRC：與音檔同主檔名的 `.lrc`；編碼依 D2 第 4 點（BOM → UTF-8 → CP932）。
- 已入庫的 FLAC／Ogg 歌曲：原始標籤已存在 `import_items.info`，遷移時直接回填，不必重新下載。
- 時間軸格式 `[mm:ss.xx]`，含 `[offset:]`；播放頁同步顯示目前一行，點一行可跳到該處。

### 播放次數與歷史

- 播放次數＝達到 D9 門檻（`counted`）的播放數。
- 歷史頁：最近的播放（含時間、從哪張專輯播放），以及近 30 天最常播放的歌曲。

### 網頁端

- 歌曲列右側「更多」選單：下一首播放、加入佇列、加入歌單、收藏、前往專輯。
- 專輯頁：收藏專輯、整張加入歌單。
- 正在播放：收藏、歌詞（寬螢幕在右側取代佇列；手機以分頁切換「佇列／歌詞」）。
- 曲庫分頁增加「歌單」「收藏」；歌單頁可改名、刪除、移除項目、拖曳排序。
- 收藏狀態由客戶端一次載入全部 ID 後在本地判斷，所有清單共用，不必每個查詢都帶旗標。

## P2-2 整理

- 編輯只改資料庫，不改寫音檔（計畫書 §4）。可編輯：歌曲（曲名、歌手、版本、類型）、專輯（名稱、專輯歌手、日期、封面）、收錄（碟號、曲序、所屬專輯）。
- 每次修改寫入 `edits`：對象、欄位、舊值、新值、來源（`user`／`identify`）、同一操作的群組 ID。撤回只還原該群組實際改過的欄位；欄位之後又被改過時列為衝突、不覆蓋，回報給使用者（計畫書 §4「撤回不覆蓋後續人工修正」）。
- 恢復原標籤：取 `import_items.info` 保存的原始標籤重新套用，同樣寫入修改紀錄、可撤回。
- 專輯合併：把一張專輯的收錄移到另一張；拆分：選取收錄移到新專輯。刪除專輯只解除收錄，被其他收錄或歌曲引用的音檔不刪除。
- 別名：`aliases` 讓歌手、專輯、歌曲有其他名稱（羅馬字、舊名、簡稱），一併建入搜尋索引。
- 搜尋正規化：在 NFKC 與小寫之外，片假名轉平假名、去除長音以外的空白差異；索引在服務啟動時依正規化版本自動重建。

## P2-3 匯入預覽

- 批次新增 `analyzing → review → running → done` 狀態。分析階段只讀標籤、不雜湊不上傳，決定每個檔案的「匯入計畫」（專輯、專輯歌手、碟號、曲序、曲名、類型），存在 `import_items.plan`；執行階段照計畫入庫，不再逐檔重新判斷。
- 需要預覽的批次停在 `review`：網頁上傳與伺服器資料夾匯入預設預覽；BT 下載預設直接匯入（選檔時已看過內容），之後用 P2-2 的編輯整理。
- 預覽顯示每組的歌曲數、缺少的資料、偵測到的編碼、不支援的格式、與曲庫中同一音訊不同標籤的檔案（D2 第 6 點）。
- 修正：改整組的專輯名稱、專輯歌手、日期；改單曲欄位；合併兩組；把一組拆成獨立歌曲；「每個子資料夾是一張專輯」；按批次改用其他文字編碼（CP932、GBK、Big5、Latin-1）重新解碼。
- ZIP：伺服器端列出內容並檢查項目數（≤ 5,000）、單檔大小、展開總量、壓縮比（> 100 倍拒絕）、路徑逃逸；處理時逐檔解壓到暫存、用完即刪；展開總量加上 ZIP 本體超過暫存預算時拒絕並說明。檔名依 `NonUTF8` 旗標與 D2 編碼規則解碼。
- 附屬檔案（D2 第 5 點）：CUE、LOG 上傳到 Drive `sidecars/<專輯>`，記錄在 `sidecars` 並掛在專輯下；LRC 成為歌詞；掃描圖仍只上傳選中的封面。

## P2-4 轉換與分軌

- FFmpeg 位置：`KANADE_FFMPEG`，或資料目錄旁 `tools/ffmpeg`；不存在時這類檔案標示原因、其他照常（D2 第 7 點）。同時只跑一個，`nice` 降低優先權。
- 轉 FLAC：APE、TAK、WavPack、TTA、ALAC、WAV、AIFF；保留取樣率、位元深度、聲道與標籤。來源與輸出解碼後的 PCM MD5 必須相同。
- CUE 分軌：依 INDEX 01 切點逐首輸出 FLAC，pregap 併入前一軌，首軌之前的隱藏音軌為第 0 軌；以取樣數切割（CD 為每幀 588 個取樣），各軌 PCM 依序串接的 MD5 必須等於整軌 PCM MD5。CUE 的 TITLE、PERFORMER、REM DATE、DISCNUMBER、CATALOG 作為原始標籤。
- 轉換與分軌在分析階段完成，輸出放在 `staging/work/<批次>`，計入暫存預算；處理前先檢查空間。
- `import_sources` 記錄來源檔 SHA-256 與大小對應到的音檔；同一來源再次匯入直接略過。

## P2-5 RSS

- 來源：名稱、URL、更新間隔（預設 30 分鐘、最短 10 分鐘）、啟用、自動下載（預設關閉）、包含／排除規則。提供 Nyaa 範本（`https://nyaa.si/?page=rss&c=2_1&f=0&q=`，可改分類與關鍵字）。
- 輪詢：單一工作程序；依下次時間排程並加隨機錯開；帶 ETag／Last-Modified；回應上限 5 MB、每次最多 500 條；失敗指數退避（最長 6 小時）。
- 解析 RSS 2.0 與 Atom；辨識 enclosure torrent、`.torrent` 連結、magnet、`nyaa:infoHash`（組成 magnet）、`nyaa:size`、`nyaa:seeders`。只有詳情頁的條目標示「無法直接下載」。
- 去重：來源＋GUID 唯一；正規化連結與 infohash 用來合併不同來源的同一種子、標示已下載過。每個來源保留最近 1,000 條。
- 規則：包含規則每行一組，行內所有詞都要出現、任一行符合即可；排除規則任一行符合就排除；比對前做 P2-2 的正規化。
- 自動下載：啟用後，只對「啟用之後新出現」的條目生效（首次與每次啟用都先建立基準）；建立下載後自動採用預設勾選，空間不足時停在選檔並顯示原因。
- 搜尋：預設在已取得的條目中篩選；Nyaa 這類網址含 `q=` 的來源可「在來源站內搜尋」，結果即時取得、不入庫。

## P2-6 Drive 與資源

- 增量對帳：保存 Changes API 的 page token，每 10 分鐘取一次變更。曲庫音檔被刪除或移到垃圾桶時標為 `missing`（不刪資料），恢復後回到 `verified`；首頁「待整理」顯示遺失數量。手動「完整對帳」分批列出平台資料夾，比對所有已知 file ID。
- 收件匣（D6）：平台資料夾下的 `inbox/`。音檔以 Range 讀檔頭解析、用 Drive 的 `sha256Checksum` 去重，再以伺服器端移動歸入 `library/`，不重新上傳；圖檔可作封面；不支援的格式下載到暫存走一般轉換流程。
- 低磁碟：每 30 秒檢查一次。低於保留空間時依序：清可淘汰快取 → 停止預載 → 暫停進行中的下載、拒絕新上傳與新下載；未上傳的資料不刪。恢復後自動繼續被暫停的下載。狀態顯示在任務頁。
- 日誌：服務自己寫檔並輪替（10 MB × 5）。
- 重啟恢復實測：在上傳、匯入、轉換、下載進行中強制結束服務，確認重啟後能接續且不產生重複遠端檔案。
